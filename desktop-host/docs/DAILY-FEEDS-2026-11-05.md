# GitHub／Yahoo 每日資訊元件（0.7.6）

新增兩張預設開啟的桌面卡片，舊版設定不必遷移，也不改寫既有外觀／日曆 JSON：

- **GitHub 每日熱門**：讀取 `https://github.com/trending?since=daily` 的前 5 個專案，顯示名稱、簡介與來源提供的當日 star 文字。這是 GitHub 的當日 Trending 排名，並非自行計算所有專案的成長率，也不把累積星數冒充當日新增星數。
- **Yahoo 最新新聞**：讀取 `https://tw.news.yahoo.com/rss`，依有效發布時間排序、去重，取 5 則標題與原文網址。僅涵蓋該台灣 RSS 當時提供的內容，不下載新聞全文或圖片。

## 更新及操作

Atmos 啟動時讀取本機快取，同一天已有成功資料便沿用；每分鐘檢查台北日期是否跨日，跨日或沒有資料時抓取。休眠、離線或關機錯過更新時，在 App 恢復運作後補抓，不建立 Windows 排程。失敗後保留上次資料並標示更新失敗／快取時間，30 分鐘後重試。每個來源同時只允許一個請求。來源未滿 5 個有效項目、結構變動或網路錯誤不覆蓋上次成功快取。

在「桌面元件 → 每日資訊元件」可各自開關、設定 X／Y 與字級，按「儲存每日元件設定」立即保存。管理預覽的標題列亦可拖曳定位，放開時保存；一般預設位於左下與右下。本機首次更新時，因原時鐘已放在右下，僅把新卡片初始化為左側上下，保留原時鐘及日曆位置；既有每日元件設定不覆寫。卡片內容過長可捲動。桌布宿主仍保持原有桌面輸入政策，不宣稱桌布上的超連結已經過人工點擊驗證。

這些設定由所有螢幕共用，獨立於原本「套用變更」的外觀草稿。停用某個元件會停止該來源後續的定期抓取（已發出的請求可能完成）；重新啟用後按既有快取與重試規則更新。關閉 Atmos 時不另外留下資料抓取程序。

## 設定與 Agent 介面

資料存於全域 store：`daily-feed-settings.json`、`daily-feed-github.json`、`daily-feed-yahoo.json`。設定與快取使用原有本機原子寫入方式；不要直接修改快取冒充抓取結果，也不要修改 `live.json` 加入這些欄位。

現有已認證管理連線可使用 `GET /api/daily-feeds` 讀取設定、來源、更新時間、錯誤與項目。管理角色可提交 `POST /api/daily-feeds`，格式為 `schemaVersion: 1`、剛讀到的 `expectedRevision` 與完整 `cards`；`cards` 僅有 `github`、`yahoo`，每張卡包含 `enabled`、`x`、`y`、`fontSize`。位置為 0–100，字級為 12–28 整數。衝突回 409，須重新讀取、合併，不自動覆蓋。桌布／螢幕保護角色僅能讀取。沿用 session、同源及 Fetch Metadata 保護，不提供匿名設定入口。

遠端來源固定，不接受任意 URL、登入資訊、HTML 模板或腳本。請求不攜帶使用者設定、token 或新聞帳號，拒絕重新導向，12 秒逾時、2 MiB 上限。只從來源擷取文字與白名單 HTTPS 原文網址；呈現使用 DOM `textContent`，不執行上游 HTML。
