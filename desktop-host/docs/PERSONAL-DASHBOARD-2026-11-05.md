# Atmos — 你的個人資訊桌面（0.7.7）

Atmos 的主定位是 **Personal Dashboard／個人資訊桌面**：把關心的資訊、生活安排與系統狀態，放進自己設計的動態桌布。動態桌布提供氛圍，資訊元件提供內容，JSON／Agent 介面提供自動化。保留 Atmos Wallpaper 應用程式身分、安裝目錄、原桌布還原及既有使用者設定，不另建雲端帳號或服務。

第一版落實三項功能：自訂 RSS／Atom、資訊來源管理、資訊卡片配置範本。既有日曆、待辦、時鐘、CPU／RAM 仍沿用原元件，沒有把未實作的服務監控或提醒列為已交付。

## 資訊來源管理

「桌面元件 → 你的個人資訊桌面」集中管理 GitHub、Yahoo 及一個自訂 RSS／Atom 元件。各自提供顯示開關、位置、字級與資料狀態；同區提供天氣來源與日曆匯入／訂閱的導引按鈕，展開既有設定，不複製另一套開關。

- GitHub、Yahoo 維持既有每日抓取與使用者設定。
- 自訂 RSS 預設關閉：填入公開 HTTPS 訂閱網址、自訂元件名稱並啟用，按「儲存資訊來源與元件設定」。這是明確新增訂閱，不預設傳送資料給另一個來源。
- 自訂更新間隔可選 15 分鐘、1 小時、6 小時或每日（24 小時間隔）。App 運作時定期更新，睡眠／關機期間不建立額外排程，恢復後補抓。
- 支援 RSS 2.0 與 Atom 基本條目，依有效日期排序、去重，最多 5 則；短清單與有效空清單也支援，不用示範項目湊數。只呈現標題、時間及 HTTPS 原文網址，不顯示整篇 HTML。
- 啟動沿用符合來源身分的持久快取；失敗保留舊資料並標示狀態，30 分鐘後重試。換來源即清除舊來源的畫面快取，舊請求晚到也不能覆寫新來源。
- 「取消本區草稿／重新讀取」只取消本區來源／資訊卡草稿，不清除外部的場景或元件草稿。來源設定採獨立版本，另一個管理頁或 Agent 修改後，本頁不能靠背景重新讀取悄悄推進草稿基準版本再覆蓋。

訂閱 URL 可能含私人查詢參數，保存在本機設定及已認證 API；不要把原設定或快取放到公開 Git。API 不接受 HTTP、帳密 URL、localhost 或直接私有 IP；抓取沿用日曆的公開 DNS 檢查、連線位址綁定及逐跳重新檢查，拒絕私有網路與重新導向內網。12 秒、1 MiB 上限；外部實體宣告拒絕，CDATA 僅當文字處理，不執行上游腳本。

## 配置範本

提供「左側資訊欄」、「左右資訊」、「上方資訊」。選擇後按「預覽配置範本」，只在本管理預覽移動三張資訊卡，不儲存、不改原場景、時鐘、日曆、來源 URL 或開關。可取消預覽；按儲存才送出有版本檢查的更新。已有任意自訂元件時仍建議查看預覽，範本不會擅自搬移其他元件以讓出空間。

本版範本範圍是資訊卡片，不是涵蓋所有元件、資料來源、場景與原生宿主的跨域交易範本。三張卡片及範本由所有螢幕共用。新增多個自訂來源、服務指標及通知列在 `../../TODO.md` 後續階段。

## Agent 接口與相容性

沿用已認證的 `GET /api/daily-feeds` 與管理角色 `POST /api/daily-feeds`，設定 `schemaVersion:1` 採向後相容的加欄位方式。保留舊版 `cards.github`、`cards.yahoo`，新增同層 `rss`：

```json
{
  "enabled": false,
  "url": "",
  "title": "我的 RSS",
  "x": 52,
  "y": 4,
  "fontSize": 16,
  "intervalMinutes": 60
}
```

先 GET 取得完整設定與 revision，再提交 `{schemaVersion:1, expectedRevision, cards, rss}`。CAS 衝突回 409，先重新讀取、合併。舊客戶端只送 cards 時，現有 rss 保留；舊檔缺 rss 時只在讀取時補預設，沒有設定變更就不改寫原始位元組。不要直接修改 `live.json` 或資料快取來控制來源。

範本的純函式在 `implementation-p4_2_5/src/dashboard-layouts.mjs`，僅回傳副本，不送網路或修改狀態；Agent 亦可讀其座標並透過同一 API 明確提交。不得把未配置的來源、快取或 renderer ACK 當作新抓取／人眼可見的證據。

格式參考：[RSS 2.0](https://www.rssboard.org/rss-specification)、[Atom RFC 4287](https://www.rfc-editor.org/rfc/rfc4287)。本版提供常見條目顯示，不宣稱完整實作兩份規格所有擴充。
