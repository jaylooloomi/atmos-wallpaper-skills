# 0.7.11 記憶體配置與資訊省電長測

## 修正與適用範圍

快照及 ACK 熱路徑原先反覆解析包含歷史與收據的完整 live 記錄。現在每個 Store 只保留一份已驗證的唯讀 head 投影，回傳防禦性副本；檔案識別、長度或時間戳改變即失效，同一程序寫入也立即失效，且最多五秒強制重新驗證。交易、回復與歷史操作繼續完整讀取及驗證，沒有直接修改使用者設定檔。

宿主 health 不再重複讀取完整 live 記錄。分類標籤、資訊卡及政策狀態只有內容改變才更新 DOM；隱藏的桌布診斷與尚未展開的管理頁診斷不再每次 ACK 序列化 JSON，僅保存最新一份證據，展開時呈現。錯誤狀態不會被舊的成功證據覆蓋。

0.7.9 的早期診斷發現 WebView 仍增長，因此追加修正最終建置的時鐘來源：原本時間及日期每秒各建立一個 Intl.DateTimeFormat，改成各保留單一 formatter，格式／語言或本機時區 offset 改變才更換；24 小時制不再取得不用的 dayPeriod parts。日期、AM／PM 及數字更新沿用文字節點，不每秒替換子樹，減少觸發整頁 childList observer 的唯讀／投影處理。設定、時區、秒數、跨日與語言更新均保留。測試直接檢查最後生成的 app.js，避免較早建置的最佳化被後續多語步驟覆蓋。

資訊省電政策只在切入時清空一次背景 Canvas，相同政策反覆回報不再清空；切回一般模式再進入仍正確清空。這是實際避免多餘繪圖，不以動畫 drawCount 代替所有 Canvas／GPU 工作的證據。

0.7.10 的完整長測仍觸發增長檢查，因此 0.7.11 進一步減少閒置 DOM 工作：已由 Intl 格式化的時鐘／日期、私人資訊卡變動不觸發整頁翻譯；桌布忽略隱藏管理區的翻譯事件。翻譯的 WeakMap 記錄加入語言，未變動的文字／屬性不重譯；真正內容或語言變更仍更新。唯讀控制只在新增控制項時重新鎖定，不因每個狀態文字變化掃描全部按鈕。番茄鐘與資料來源的未變動文字沿用既有節點。凍結 prototype 沒有修改，番茄鐘修正在目前產品建置階段加入並檢查最終產物。

同版加入自己 WebView 的原生唯讀診斷，每分鐘只呼叫固定的 `Runtime.getHeapUsage` 與 `Memory.getDOMCounters`。不開 DevTools 視窗／除錯連接埠、不執行任意 JS 或 CDP 指令、不強制 GC。探測回呼不持有 WebView、最多 17 個視窗記錄，卡住的請求不持續累積；舊回呼不能覆蓋新視窗的結果。更新期間保留有時間戳且 90 秒內的真實計數，失敗／過期／缺失不填零。摘要分別去重 heap 與 DOM 的原生採樣時間，移除視窗名稱及系統識別。這些是正常 GC 週期的當下計數，不是強制回收後 retained heap。[WebView2 API](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_11)、[heap 計數](https://chromedevtools.github.io/devtools-protocol/v8/Runtime/#method-getHeapUsage)、[DOM 計數](https://chromedevtools.github.io/devtools-protocol/tot/Memory/#method-getDOMCounters)。

這些修正降低已確認的配置與 DOM 更新壓力，不能單憑程式修改把舊版所有 private bytes 增長都認定為已找到的 JS 保留洩漏。

## 隔離配置實驗

`node desktop-host/scripts/test-snapshot-allocation.mjs` 使用各自新建的合成 store 與 Node 子程序，比較 6,000 次快照。舊路徑讀取 live 6,000 次、共 564,906,000 bytes；快取熱窗內讀取零次，耗時由約 10.45 秒降至 2.81 秒。正式快取仍會最遲每五秒重新驗證，並非永久不讀磁碟。

此實驗僅在隔離子程序使用 `--expose-gc`。兩邊強制回收後的 retained heap 差值都很小（約 220 KB 與 110 KB），因此它證明配置壓力下降，不能證明舊版實機的全部記憶體增長原因。證據：[配置 A/B 摘要](../evidence/snapshot-allocation-ab-2026-11-05.json)。

## 限制

程序 private bytes 包含配置器、GC 與快取影響，不等於 retained JS heap 或唯一實體 RAM。GPU 指標是已歸屬程序中最忙的實體引擎，不是整張 GPU 百分比；瓦特／焦耳沒有有效量測來源。本次省電負載與舊 0.7.1 動畫負載不同，不構成舊／新兩小時的受控 A/B，也不保證其他硬體或任意長度均零洩漏。原生掛載與 ACK 不取代人工可視性驗證；依本輪要求未做人工測試。
